# P0 真实业务评测基线

更新时间：2026-10-16（Asia/Shanghai）。

本轮使用真实业务文档 `《国家基本公共卫生服务规范》第三版.pdf`，完成了一个隔离知识库的检索和问答试跑。原始题集、检索响应和问答响应保存在被 Git 忽略的 `eval/datasets/private/`：

- `public-health-p0-pilot.jsonl`：20 条 P0 试跑样本，包含检索、问答、引用、拒答和权限结果。
- `p0-search-results.json`：20 条管理员身份的检索原始响应。
- `p0-qa-results.json`：18 条普通/版本题的真实问答原始响应。
- `public-health-p0-baseline.md`：完整指标、边界和下一步。

## 已完成的 P0 修复

服务端现在会在引用校验前识别结论性范围拒答，例如“没有找到该规范直接规定……的依据”“无法据此回答”和“仅凭该规范不能判断”。命中后统一写入 `outcome=no_answer`、固定拒答文本并清空引用；局部否定但仍给出证据支持结论的回答仍保持 `answered`。新增回归测试覆盖带引用拒答、变体措辞和版本题防误拒。

对已保存的 18 条真实问答原文离线重放校验后，014、015、016 均归一为 `no_answer` 且引用数为 0，018 仍为 `answered` 且保留 1 条引用。这个结果验证了终态规则，但不替代重新调用真实链路后的 20 条正式基线。

问答代码已将 `pipeline_retrieval_ms`、`generation_ttft_ms`、`generation_stream_ms`、`answer_persist_ms` 和 `pipeline_total_ms` 合并写入对应检索 Trace 的 `timings` JSON。模型客户端对所有问答路径统一发送服务端 `max_tokens`，并显式发送 Open WebUI/Ollama 的 `params.think=false`。

独立网关短请求实测：默认思考模式冷启动首 token 约 31.0 秒；同类请求关闭思考后热请求首 token 约 1.1 秒、总耗时约 1.2 秒，输出 6–10 token。此前 60–160 秒级端到端耗时主要由生成模型冷加载/思考等待造成，仍需用真实业务题集重跑并完成冷/热、并发和模型驻留容量验收。

修复后的真实业务题 `public-health-015` 已重新执行一次：最终 `outcome=no_answer`、引用数为 0，流式事件只发送校验后的固定拒答文本。该次 Trace 记录 `pipeline_retrieval_ms=5907.19`、`embedding_ms=5108.53`、`generation_ttft_ms=35184.33`、`generation_stream_ms=36158.48`、`pipeline_total_ms=42124.02`。这次结果确认生成模型冷加载仍是主要延迟来源，不能把热请求的约 1 秒结果当作生产 SLA。
