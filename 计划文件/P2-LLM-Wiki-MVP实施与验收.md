# P2：LLM Wiki MVP 实施与验收

实施日期：2026-10-16。

## 功能与使用流程

在「知识库」列表选择「词条管理」，默认查看词条列表；点击「新建词条」或「编辑」才展开表单，可随时返回列表。填写定义、负责人、有效期，并搜索、勾选当前发布版本中的原文片段；来源可打开对应文档页。知识库读者可查看已发布词条，管理者可维护和审核。

完整流程：新建草稿 → 关联原文 → 提交审核 → 审核发布 → 别名参与检索 → 问答引用显示关联词条和版本 → 查看历史或退役。

- 词条包含名称、定义、别名、负责人、有效期、来源片段和版本。
- 状态包含草稿、待审核、已发布、已退役。待审核可退回草稿，退役可重新启用为草稿。
- 修改内容会回到草稿，必须重新审核才能进入检索。版本检查阻止旧页面覆盖新版本。
- 每次内容和状态变更保存不可变快照，并写入审计记录。
- 提交审核和发布须具备有效负责人及当前 Release 的有效原文来源；过期词条不能发布。
- 只有已发布、在有效期内、具备当前 Release 有效来源的词条参与查询。空间、知识库权限继续生效。

## 检索与引用边界

命中标准名或别名后，以标准名扩展关键词/BM25 排序，并使用该词条关联的原文证据。答案依据仍是原文片段，人工填写的定义不会直接替代原文成为事实来源。引用侧栏显示词条名称、版本及已发布状态，Trace 记录命中的词条。

为避免「0～6 岁儿童健康管理」和「0～36 个月儿童中医药健康管理」混用，明确命中已审核词条时，仅保留该词条关联且仍有效的原文。未命中词条的问题继续使用原有检索链路。

维护者必须关联足够完整的来源：仅关联一页时，问答只能使用该页；跨章节问题应关联所有必要片段。发布文档新版本后，旧来源若不在当前 Release，词条不会继续通过旧证据参与检索，需重新关联并审核。

## MVP 范围

本次完成手工维护、人工审核、检索接入和引用追溯闭环。未包含自动抽取并发布、独立图数据库、完整 Ontology、模型微调或自动重新关联新文档版本。当前具备管理权限的人员可审核发布，尚未强制提交人与审核人分离。

真实生成仍依赖现有模型服务的可用性和时延；本次两轮生成在检索返回 1 条证据后均发生 READTIMEOUT，未获得修复后的完整生成答案。已确认别名检索只返回第 33 页关联证据，尚不能宣称完整生成及引用实测通过。需模型服务恢复后补验最终答案。

界面补验：修复 AppDialog 透明壳与业务卡片缺失，按项目 `--spacing: 1px` 采用明确像素间距；默认列表和新建/编辑分离，表单按基本信息、负责人/有效期和原文来源分组。浏览器确认卡片为白色、内边距 24px、复选框 16px、无横向溢出，并验证返回列表、编辑和停用确认及服务端持久化。

滚动补验：弹窗高度最多 760px，矮屏时为视口减 40px；标题和工具栏固定，列表与版本历史在内部内容区滚动，编辑字段独立滚动，取消/保存固定在底部。浏览器实测 981px 高视口中弹窗 760px、字段区域 426px（内容 1060px），保存按钮仍在可见范围内。
