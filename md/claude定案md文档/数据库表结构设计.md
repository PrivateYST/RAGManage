## 7. 性能优化建议

### 7.1 分区策略
```sql
-- documents 表按创建时间分区（每月一个分区）
ALTER TABLE documents
PARTITION BY RANGE (YEAR(created_at) * 100 + MONTH(created_at)) (
    PARTITION p202609 VALUES LESS THAN (202610),
    PARTITION p202610 VALUES LESS THAN (202611),
    ...
);
```

### 7.2 索引优化
```sql
-- 复合索引优化高频查询
CREATE INDEX idx_user_status_latest ON documents (user_id, status, is_latest, deleted_at);
CREATE INDEX idx_conv_user_time ON conversations (user_id, status, last_message_at DESC);
```

### 7.3 数据归档
```sql
-- 定期归档超过1年的对话历史到历史表
CREATE TABLE messages_archive LIKE messages;
-- 定期迁移数据
INSERT INTO messages_archive SELECT * FROM messages WHERE created_at < DATE_SUB(NOW(), INTERVAL 1 YEAR);
DELETE FROM messages WHERE created_at < DATE_SUB(NOW(), INTERVAL 1 YEAR);
```

## 8. 备份与恢复

### 8.1 备份策略
- **全量备份**：每天凌晨 3:00
- **增量备份**：每 6 小时一次
- **备份保留**：保留最近 30 天

### 8.2 备份脚本
```bash
#!/bin/bash
mysqldump --single-transaction --routines --triggers \
  --databases rag_knowledge_base \
  > /backup/rag_$(date +%Y%m%d_%H%M%S).sql
```

## 10. 注意事项

1. **软删除**：所有核心表使用 `deleted_at` 实现软删除，便于数据恢复
2. **时区**：所有 DATETIME 字段使用 UTC 时区，应用层转换
3. **JSON 字段**：MySQL 8.0+ 支持 JSON 索引，可根据实际查询需求添加虚拟列索引
4. **外键约束**：建议在应用层控制，不使用数据库外键（提升性能）
5. **分页查询**：大表查询使用游标分页（基于 ID），避免 OFFSET 性能问题
