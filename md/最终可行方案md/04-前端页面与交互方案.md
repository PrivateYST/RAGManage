# 前端页面与交互方案

## 1. 视觉与布局

统一采用 shadcn-vue 的中后台风格：侧边导航 + 顶部面包屑 + 主内容，浅色/深色语义 token，规整表格与标准表单。圆角、字号、间距以设计 token 统一，不逐页自由发挥。

桌面优先，同时保证较窄屏幕能够展开筛选、横向查看表格和完成问答。使用克制的主色，不使用强渐变、营销式大标题或夸张动画。

## 2. 页面清单

| 页面/路由 | 主要内容 | 核心操作与状态 |
|---|---|---|
| /login | 账号/密码、登录错误 | 禁重复提交，不区分账号不存在与密码错误 |
| /knowledge-bases | 知识库表格、权限、发布状态 | 创建、搜索；空态引导建库或申请权限 |
| /knowledge-bases/:id/documents | 文档表格、类型/状态过滤、待发布提示 | 上传、版本、重试、停用；区分上传完成和索引可用 |
| /documents/:id | 版本时间线、原文、解析、切片、警告 | 切片定位原文；旧发布版和新草稿同时可辨 |
| /knowledge-bases/:id/search-test | 问题、候选、来源、排名、耗时 | 管理员比较当前与候选 release；避免分数跨模型直接比较 |
| /knowledge-bases/:id/releases | 当前发布、构建列表、差异、质量结果 | 构建、取消、发布、回退；显示影响文档数 |
| /knowledge-bases/:id/settings | 信息、成员、预设策略、高级参数 | 展示变更是即时运行变化还是需重建；权限矩阵明确 |
| /chat/:conversation? | 库选择、历史、消息流、引用侧栏 | 发送/停止/反馈；库未就绪不能提问 |
| /tasks | 状态、类型、进度、失败项 | 重试、取消；完成数/总数比虚假百分比重要 |
| /admin/users | 账号、状态、组织角色 | 新建/停用/重置，审计记录 |
| /admin/models | 已登记端点、健康状态、支持模型 | 管理员登记；密钥不回显，模型选择来自白名单 |
| V1.1 记录导入 | 字段映射、差异预览、导入任务 | 明确 upsert/delete、全量/增量和数据水位 |

## 3. 三个主要操作流程

### 上传与发布

选择文件 → 上传 → 后台解析/切片/嵌入 → 文档详情检查 → 候选构建就绪 → 管理员发布。

上传弹窗只描述文件结果，不让用户误以为上传即生效。文档行显示“处理中/处理失败/待发布/已发布/部分解析/已停用”。部分解析显示受影响页/区域及局限，禁止隐形丢资料。

### 问答与引用

进入已发布知识库 → 输入问题 → 阶段状态 → 流式答案 → 来源编号 → 侧栏原文与位置。

拒答提供“资料不足/来源冲突/索引未就绪”等可行动原因。重试、复制、反馈各有明确状态；失去权限后清理当前页面敏感状态并返回无权限页。不得在流式结束前把未经验证的模型引用伪装成可靠来源。

### 配置与重建

选择预设 → 展示影响 → 保存新配置版本 → 如有索引变化创建构建 → 检索测试 → 发布。

top-k/提示词显示“不需要重新处理文档”；嵌入模型/切片变更显示预计影响范围与后台任务。时间估计只有在已有吞吐样本时显示，否则显示待测。

## 4. Vue 组件与状态边界

使用 Composition API 和 `<script setup lang="ts">`。页面负责组合，异步状态在 composables；Props 下行、Events 上行。服务端数据不在 Pinia 和页面中复制维护两套真相。

| 组件/composable | 单一职责 | 数据契约 |
|---|---|---|
| AppShell | 导航、面包屑、用户菜单 | 当前路由/身份 |
| DocumentFilters | 文档过滤输入 | modelValue；update:modelValue |
| DocumentTable | 展示文档与允许的行操作 | rows/loading/permissions；open/retry/disable |
| UploadDialog | 文件选择与上传结果 | kbId/open；uploaded/update:open |
| ChunkPreview | 展示结构和位置 | chunks/selected；select/locate |
| ReleaseDiff | 发布前内容差异 | current/candidate；无写业务副作用 |
| ChatMessage | 渲染文本、状态与引用入口 | message；citation/feedback |
| CitationPanel | 加载授权原文预览 | messageId/evidenceNo；close |
| useChatRun | POST 流解析、取消、恢复状态查询 | start/cancel/state/events |
| useTaskPolling | 状态轮询、退避、清理 | taskId；state/retry/cancel |
| useDocuments | 查询参数、游标与服务端变更 | filters；rows/loading/actions |

Pinia 保存会话身份、当前组织与 UI 偏好；知识库列表/任务以服务端结果为准。离开页面取消轮询和请求，重复发送用幂等键保护。

## 5. 交互与可访问性验收

- 所有页面覆盖 loading/empty/error/forbidden/stale；失败可恢复，不以空表代替错误。
- 表单提供 label、字段错误和提交错误；弹窗管理焦点，支持键盘关闭与返回触发点。
- 表格用真实表头，状态不只靠颜色；分页、筛选后重置 cursor。
- 流式回答减少 screen reader 逐 token 播报；结束后通知完成。
- Markdown 渲染禁用原始 HTML或严格清理；限制危险链接协议，不执行文档脚本。
- 删除/发布弹窗展示具体对象和影响；不把每次读取操作都加确认。
- 自定义颜色、间距、圆角均通过 token；业务页不直接修改基础组件内部样式。

## 6. 前端交付顺序

P17 先做可上传与看状态的管理页，P18 做问答引用，P19 补配置/发布/调试，P23 做完整用户流程验收。模型质量不合格时不投入复杂大屏、图表或全量配置面板。
