# 数据模型与索引生命周期

## 1. 通用约束

正式 DDL 由 P09 迁移实现并测试。这里固定字段语义与关联约束，不将示意表格伪装成可运行 SQL。

- 主键 BIGINT identity，JSON API 中 ID 序列化为字符串，避免 JavaScript 精度问题。
- 所有时间 TIMESTAMPTZ，以 UTC 存储；所有业务作用域关联包含 tenant_id。
- 不可变对象创建后禁止编辑内容，更新生成新行。状态与生命周期字段可按状态机转换。
- 父实体提供 `(tenant_id,id)` 或 `(tenant_id,kb_id,id)` 唯一键；子实体复合外键保证归属一致。
- tenant 从 session 与成员关系确定。跨租户作业必须显式选择作用域并审计。
- 配置只保存 model_endpoint_id/secret_ref，不保存明文密钥，也不允许普通成员输入任意网络 URL。

## 2. 表与关键字段

各表默认有 id、created_at；可变实体增加 updated_at/lock_version。以下省略这些公共字段。

| 表 | 关键字段 | 关键约束 |
|---|---|---|
| tenants | name,status | 状态控制整个组织访问 |
| users | login,password_hash,status | login 唯一；删除账号不级联删除业务内容 |
| tenant_members | tenant_id,user_id,role,status | 组织与用户唯一 |
| sessions | user_id,token_hash,expires_at,revoked_at | 仅存随机 session token 的 hash，可立即撤销 |
| knowledge_bases | tenant_id,name,active_release_id,active_runtime_id,content_epoch,auth_epoch | 发布/运行指针必须属于本库 |
| kb_members | tenant_id,kb_id,user_id,role | 每库每用户唯一；必须也是有效组织成员 |
| datasets | tenant_id,kb_id,name,is_default | 每库恰有一个默认数据集，由事务创建；首版 UI 隐藏 |
| documents | tenant_id,kb_id,dataset_id,title,status,desired_version_id,deleted_at | 稳定逻辑身份；desired 不等于已发布 |
| document_versions | document_id,version_no,storage_key,sha256,mime,size,parse_status,warnings | `(document_id,version_no)` 唯一；原文件不可变 |
| model_endpoints | type,provider,base_url,secret_ref,allowed_models,health_status | 仅组织运维管理员维护；网络目标白名单 |
| ingestion_profiles | tenant_id,kb_id,definition,definition_hash | 解析/切分/tokenizer/词法分析规则快照 |
| embedding_profiles | model_revision,dimension,dtype,instructions,normalization,definition_hash | 全部编码规则不可变；endpoint 副本须校验同一配置 |
| runtime_profiles | tenant_id,kb_id,retrieval,rerank,generation,prompt,definition_hash | 不可变，绑定允许的 embedding profile/索引契约 |
| index_builds | tenant_id,kb_id,base_release_id,input_epoch,ingestion_profile_id,embedding_profile_id,state | 同库初期只允许一个运行构建；服务端锁与部分唯一索引保证 |
| index_build_items | build_id,document_version_id,artifact_id,state,error | 每构建每源版本唯一；明确成功/失败项 |
| document_artifacts | tenant_id,kb_id,document_version_id,ingestion_profile_id,state | 同源同处理 profile 唯一；包含结构树对象键与 manifest |
| chunks | tenant_id,kb_id,artifact_id,ordinal,content,embed_text,token_count,section_path,locator,lexical_terms,lexical_tsv | `(artifact_id,ordinal)` 唯一；就绪后不可修改 |
| chunk_embeddings | tenant_id,kb_id,chunk_id,embedding_profile_id,embedding | 初期 vector(1024)；`(chunk_id,embedding_profile_id)` 唯一 |
| kb_releases | tenant_id,kb_id,build_id,embedding_profile_id,manifest_hash,state | ready 后清单不可变；发布动作单独审计 |
| release_items | tenant_id,kb_id,release_id,document_id,document_version_id,artifact_id | 每个 release 每文档仅一版；全部关联同库 |
| tasks | tenant_id,kb_id,type,state,idempotency_key,attempt,lease_until,fencing_token,error | 幂等键唯一；过期 worker 不得覆盖新 worker 结果 |
| task_items | task_id,target_id,stage,state,attempt,error | 逐项恢复；不可只靠 cursor 假定前面全部成功 |
| outbox_events | tenant_id,event_type,payload,state,next_attempt_at | 与业务任务同事务提交；重复投递由任务幂等消解 |
| conversations | tenant_id,kb_id,owner_user_id,title,status | 单会话单库，仅所有者访问 |
| messages | tenant_id,conversation_id,role,content,state,request_id,release_id,runtime_id,usage | request_id 防重复；同会话只允许一个进行中的回答 |
| message_citations | message_id,chunk_id,document_version_id,locator,evidence_no | 保存来源版本定位与必要引用片段；独立于短期追踪 |
| message_evidence | message_id,document_id,document_version_id | 保存全部进入上下文的来源，用于删除/授权后隐藏历史回答 |
| retrieval_traces | tenant_id,kb_id,user_id,message_id,query,rewritten_query,profiles,timings,status | 保存实际版本，默认仅有权限的调试者读取 |
| retrieval_trace_items | tenant_id,trace_id,created_at,chunk_id,route,rank,score,fused_rank,rerank_score,in_context | 明细带时间；避免默认复制每个候选完整正文 |
| feedback | tenant_id,message_id,user_id,rating,reason | 用户只能评价自己可见回答 |
| audit_logs | tenant_id,actor_id,action,target,change_summary,request_id | 审计业务变化，不写密码和模型密钥 |

索引优先覆盖成员查询、文档列表、任务状态、release_items、来源引用、trace 时间；大表游标分页。不得只因为“以后会大”就引入时间分区。

## 3. 内容与索引版本职责

| 变更 | 动作 |
|---|---|
| prompt、top-k、RRF 权重、重排/生成模型 | 新 runtime；验证后切换，不重嵌入 |
| 文档标题只用于展示 | 改展示元数据；如果标题用于 embed_text，则属于下项 |
| embed_text、切片、tokenizer、解析器 | 新 artifact；重算实际变化的向量 |
| 词法分词词典/规则 | 新处理产物/词法索引；向量输入未变可复用向量计算结果 |
| embedding 模型/revision/维度/指令/归一化 | 新 embedding profile 与构建，禁止原索引内混写 |
| 文件新版本 | 创建内容版本，新建/复用产物，新 release 替换该文档 |
| 删除/停用 | 即时更新有效性并增加 epoch；后续发布整理清单 |
| 知识库成员变化 | 增加 auth_epoch、撤销相关访问；无需重建向量 |

索引构建是处理任务，release 是可用内容快照，两者不等同。一个 release 可复用旧构建的已就绪 artifact；所有 release_items 必须有同一 embedding profile 的向量产物。

## 4. 构建和发布

1. 上传生成新 document_version，更新 desired_version，增加 content_epoch；旧 release 保持可用。
2. 创建 build，记录 input_epoch、base_release、需要发布的全部有效文档版本清单。单文档更新复用其余 artifact，不重新调用所有嵌入。
3. Worker 逐项解析、切片、嵌入；任何必需项失败，整个 build 不进入 ready。用户可另建明确排除失败项的构建，不能静默漏文档。
4. 校验清单条数、向量数/维度/profile、词法产物、原文定位和质量门槛。
5. 生成候选 release，状态 ready；只允许管理员检索预览。
6. 发布事务锁住 knowledge_base，检查 content_epoch == input_epoch、active_release == base_release、当前权限、所有产物仍完整。
7. 通过后 CAS 切换 active_release_id，并记录对应 runtime、发布审计；冲突返回 409，不自动覆盖别人的更新。
8. 若构建期间有新修改，重新生成清单并复用已完成产物，补齐后再验证；初期不做复杂双写追平。

构建状态：queued → running → validating → ready，分支为 failed/cancelled。发布动作不修改 ready 清单；active 指针是唯一当前版本来源。

新知识库无 active release 时返回 INDEX_NOT_READY，而不是让模型自由回答。

## 5. 回退、删除与清理

- 回退选择仍保留的 ready release 与兼容 runtime，锁库验证后切换；模型 endpoint 必须仍能服务其 profile。
- 回退不修改 desired_version：下一次构建继续以当前编辑意图为准；UI 明确“当前发布版本”和“待发布版本”。
- documents 的当前停用/删除状态永远优先于历史 release 清单。回退不会重新开放已删除内容。
- 内容删除事务标记 deleted_at、增加 epoch。新检索、原文、引用和历史回答读取均检查当前状态。
- 生成请求开始/组装上下文/输出前检查授权与有效性；输出中按事件或短周期检查 auth/content epoch。发现撤权/删除停止流，标记 invalidated，隐藏已保存回答。已经传送到客户端的字节无法撤回，这一边界必须明确。
- 会话答案只要依赖的任一 message_evidence 来源当前不可见，默认整体隐藏该答案，显示“来源已不可用”；不能仅隐藏引用而继续展示答案正文。
- 标记删除后先隔离，物理清理按对象引用关系做 mark-and-sweep：active/保留 release、运行 build、在途请求引用均阻止删除。显式内容删除的屏蔽无需等待物理清理。
- 消息引用在文件清理后可显示来源已删除，不承诺永远可恢复。恢复已删除内容需要独立显式操作与权限。

## 6. 向量与词法物理实现

初始一个 embedding profile，1024 维固定列，精确距离检索作为基线；后续建立 cosine HNSW。所有查询绑定 tenant、kb、release 清单、profile 以及当前文档状态。

HNSW 并不保证先应用所有关系过滤；实际可能候选不足。P21 对比精确检索，调整 iterative_scan/ef_search/max_scan_tuples，并评估知识库级部分索引或分区。部分索引的准备语句与执行计划必须测试，不为每个 prompt 版本建一个索引。

未来高维不能直接替换当前列。2560 维可验证 halfvec(2560) 索引，或模型支持的较低维输出；迁移使用单独物理表/布局，服务端白名单映射 profile 到 layout，不允许用户注入 SQL 表名。

中文词法首版：固定版本中文分词器与业务词典 + PostgreSQL simple tsvector/GIN；查询使用同一分词规则，编号保留独立规范化 token，并提供精确匹配加权。采用 ts_rank_cd 作为词法排序，明确它不是 BM25。分词器版本记录在 ingestion profile；P20 评测失败时才引入专用 BM25 服务。

## 7. 任务一致性

业务事务写 task 与 outbox；派发器投递成功后标记 outbox，崩溃可重复投递。Worker 按幂等键领取任务，使用租约与 fencing_token 更新状态，数据库拒绝旧 worker 的迟到提交。

每个 stage 写产物和 task_item 完成状态在同一事务中；调用模型发生在事务外。先查已完成产物，再计算，最终唯一约束处理并发重复。取消为 cooperative：批次边界检查；取消的构建永不自动发布。

文件先写 staging 并校验 hash，再提交元数据/任务。Worker 只读已确认对象；未被元数据引用的 staging 由清理器回收。处理不可变 object key，不直接拼接用户文件名到服务器路径。

## 8. 迁移顺序

身份/知识库/数据集 → 内容/profile → artifact/chunk/embedding → build/release → 补 active 指针外键 → task/outbox → conversation/evidence/trace → 审计反馈。

循环引用通过先建表后加外键解决；source/profile 同库约束一起落地。执行空库升级、旧版升级、重复初始化、备份恢复测试。生产结构变更采用 expand-contract，不依赖破坏性降级迁移回滚业务。
