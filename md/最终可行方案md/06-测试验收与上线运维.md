# 测试验收与上线运维

## 1. 测试层次

| 层次 | 内容 | 执行时间 |
|---|---|---|
| 单元 | 结构切片、token 预算、配置影响分类、RRF、状态转换 | 相关代码修改时 |
| 数据库集成 | 外键/唯一约束、事务、CAS、租约、幂等、发布与删除 | 迁移/数据访问变化时 |
| 服务集成 | 模型协议、错误码、文件卷、队列、outbox、流式 | 外部边界变化时 |
| 前端组件 | 关键表单、权限状态、流式异常、引用与任务 | 相关交互变化时 |
| E2E | 上传→发布→问答→引用；更新→发布；删除/撤权 | 合并与发布前 |
| RAG 离线评测 | 检索证据、答案可用、拒答、引用支持性 | profile/模型/检索变化时 |
| 性能与恢复 | ANN/并发/构建峰值、备份恢复、故障演练 | 候选发布和重大部署变化时 |

不追求形式化的固定覆盖率代替行为质量。高优先级是数据不丢、不越权、不混索引、失败可恢复。

## 2. G1/G2 质量门槛

使用 P04 的独立留出集，至少 50 条带证据/无答案标注的代表问题；调参集与留出集分别报告。对少数类别给出样本量，不夸大小样本结论。

| 指标 | 定义 | 默认验收目标 |
|---|---|---|
| Evidence Recall@10 | 有答案题中前十候选命中标注证据的题数/有答案题数 | ≥90%；多证据题另外报告全部必要证据覆盖率 |
| 答案可用率 | 答案要点正确、无关键无依据断言的题数/受评题数 | ≥85% |
| 引用支持性 | 引用确实支持相应论断的数量/被检查引用论断数量 | ≥95% |
| 无答案正确处理 | 正确拒答/澄清且未编造事实的题数/无答案题数 | ≥90% |
| 权限暴露 | 两租户、同租户非成员、撤权等回归 | 测试中 0 暴露 |
| 数据一致性 | 构建、发布、回退、删除、任务重放用例 | 关键用例全部通过 |

这些是计划目标，不是当前成绩。上线前根据场景风险确认是否加严；不能为了宣称通过而偷偷降低阈值。LLM-as-judge 可辅助分拣，关键样本须人工复核。

## 3. 质量归因与实验记录

每次评测保存：数据集版本、源文档版本、release、全部 profiles、模型实际版本、索引参数、运行环境、每题结果、候选证据、耗时和人工评分。

错误分类：解析缺失、切片断义、词法/向量未召回、重排误删、上下文截断、模型误答、引用不支持、无答案处理错误、权限/版本错误。

固定其他变量比较单路向量、词法、融合、融合+重排。记录新增延迟/显存/成本；没有收益时关闭复杂策略。任何模型升级使用独立构建和留出评测后发布，不热替换旧空间。

## 4. 关键回归清单

| 编号 | 测试 | 必须结果 |
|---|---|---|
| T01 | 两租户使用相同文档名/query | 文件、chunks、会话、trace 无交叉 |
| T02 | 同租户非成员访问已知文档 ID | 无法读文件、切片、引用和检索 |
| T03 | 撤权后继续旧会话/下载/调试 | 当前请求拒绝；进行中流停止后续输出；页面状态清理 |
| T04 | 删除来源后查看旧答案 | 依赖该来源的答案整体隐藏；回退不恢复访问 |
| T05 | 上传新版本解析失败 | 旧发布版本继续可用，失败可重试 |
| T06 | 构建期间更新源版本 | input_epoch 冲突，不发布过期快照 |
| T07 | 同时发布两个候选 | 一个成功，另一个 409，不能覆盖新指针 |
| T08 | 修改 prompt/top-k | 不重嵌入，新运行版本可以使用原 release |
| T09 | 换相同维度不同嵌入模型 | 强制新 profile/构建，不混空间 |
| T10 | 不同维度/NaN/零向量输出 | 校验失败，数据库不留“成功”坏产物 |
| T11 | 任务重复投递/worker kill | 不重复产物，完成项保留，失败项恢复 |
| T12 | 租约过期后旧 worker 提交 | fencing 拒绝，不能覆盖新结果 |
| T13 | 数据库已提交但入队失败 | outbox 补发，可观察而非永久悬挂 |
| T14 | 超大/损坏/压缩炸弹/路径文件名 | 限制生效，不越目录，不拖垮服务 |
| T15 | 文档中嵌入 HTML/指令/危险链接 | 不执行脚本，不当系统指令，无越权检索 |
| T16 | SSE 任意分片/重复/断线 | 解析稳定，一个终态，不重复生成 |
| T17 | 狭窄过滤+ANN | 与精确基线对比，候选不足不被忽略 |
| T18 | 清理过期构建/trace | active release 与历史引用关系不被错误删除 |
| T19 | 全部数据库/文件从备份恢复 | 原文和引用可打开，检索版本正确 |
| T20 | 记录增量文件缺失某 external_id | 不误删，只有显式 delete 或确认全量差异才删除 |

## 5. 性能验收口径

在 P03/P08 给出实测基线，在 P25 确定上线容量。默认试点体验目标：约定输入/输出预算下 P95 首字 ≤8s、非生成管理 API P95 ≤1s、检索+重排 P95 ≤2s；这些仅为待验证目标，目标硬件达不到时必须调整模型/部署/范围并更新报告。

完整生成时间不和首字混算：固定输出最多 1024 tokens，分别报告实际输出长度、tokens/s 和完整时间。容量报告必须包括并发 1/5/10、冷/热条件、数据量、过滤比例、后台构建是否运行、硬件与量化。

有限队列，超限返回 429 与 Retry-After；不要让请求无限排队。记录端到端延迟内排队占比。若只能承载 1 个生成请求，就按这个容量发布试点，不声明 50 并发。

存储容量包含原文件、解析产物、正文、向量、HNSW、WAL、追踪、两份构建与备份。1M 个 1024 维 float32 向量裸值约 4.096GB（十进制），这不是数据库总大小；索引和正文额外测量。SSD 空间告警从 70% 起评估、85% 阻止大型新构建，阈值可按实测调整。

## 6. 生产部署步骤

1. 准备独立生产环境，记录系统/驱动/GPU/磁盘，验证时间同步与 TLS。
2. 设置仅部署者可读的 secrets，独立 DB/Redis/文件卷；禁止开发账号访问生产。
3. 启动 PostgreSQL/Redis/存储，检查持久性与扩展版本；网络仅内部可达。
4. 备份当前数据（首次空库注明），运行受验证 Alembic 升级并记录版本。
5. 启动模型服务，检查真实 profile 与容量，再启动 API、outbox dispatcher、worker、任务回收/清理器。
6. 部署前端与 Nginx，同源代理，SSE 禁缓冲，设置上传限制、超时、限流。
7. 一次性创建组织管理员并强制设置密码；创建试点知识库/成员，导入少量真实资料。
8. 执行登录、上传、发布、问答、引用、删除、worker 重启冒烟测试。
9. 备份恢复演练通过后逐步开放用户，观察至少 5 个工作日。

以上是操作顺序；实际 shell 命令在 P24 根据锁定镜像和目录生成，不提供未经本机验证的一键上线命令。

## 7. 备份与恢复

默认内部试点候选目标：RPO ≤24h、RTO ≤4h。P26 实测确认；需要更低 RPO 时增加基础备份+WAL 归档和文件版本存储，不误认为 pg_dump 自带 PITR。

每日备份 PostgreSQL、自定义配置/profile 清单、全部被数据库引用的原文件/产物；备份加密并放在与业务设备独立的位置，初始保留 14 个日备份和 4 个周备份。密钥恢复路径独立保管并测试。

首版采用维护窗口一致性流程：暂停内容/配置写入和构建提交、等待在途写任务结束，记录 checkpoint；导出数据库并按该快照对象清单备份不可变文件；核对 hash/数量后生成 backup manifest，再恢复写入。失败时该批备份标记 incomplete，不作为有效恢复点。

恢复到隔离环境：恢复 DB → 恢复清单对象 → 校验缺失和 hash → 恢复 endpoint/profile 配置 → 重建会话凭据策略 → 健康检查 → 样本原文/引用/检索 → 记录耗时。会话 token 可全部撤销要求重新登录。未完成队列任务从数据库对账，不能直接重放来源不明的旧 Redis 队列。

删除政策必须覆盖备份：备份在保留期内可能仍包含已删除原文；恢复旧备份后在对用户开放前重放删除/撤权清单，避免恢复已禁止的数据。若业务要求即时不可恢复删除，需要专门的加密密钥销毁与备份策略，不由普通软删除承诺。

## 8. 监控、清理和故障处理

| 信号 | 行动 |
|---|---|
| 模型不可用/OOM | 限流，暂停后台嵌入，检查显存与模型并发；不切不兼容嵌入模型 |
| 队列等待持续上升 | 检查 worker、外部服务、失败重试，必要时限制新导入 |
| PostgreSQL 延迟/磁盘增长 | 看慢查询/执行计划/WAL/trace；清理策略先 dry-run，再执行 |
| 发布错误上升 | 停止发布，保留当前有效 release，检查 profile/epoch |
| 引用缺文件 | 标记故障并恢复文件，禁止返回虚假成功预览 |
| 质量回退 | 比较评测版本和来源变化，切回兼容且保留的 release/runtime |

日志带 request/task/run/trace ID，屏蔽密码、cookie、API key 和默认完整正文。追踪明细默认 30 天，审计 180 天；完整上下文仅在授权诊断时短期保存。清理分批执行并记录计数，不锁表大删。

模型故障不能自动调用未授权外部服务。通知由部署方配置到其认可渠道；本规划不包含发送外部消息的自动授权。

## 9. 上线与交接清单

- [ ] 锁文件、镜像 digest、迁移版本、模型/profile 清单完整。
- [ ] G1 质量达标，P22 关键一致性/权限回归无阻断问题。
- [ ] P25 容量/限流/SLA 有实测记录，硬件与真实数据规模匹配。
- [ ] P26 恢复成功，原文与 DB 一致，RPO/RTO 可达。
- [ ] 配置变更与 release 回退流程可演示，保留窗口明确。
- [ ] 用户理解不支持 OCR/复杂表格/任意数值统计等范围。
- [ ] 管理员能处理失败任务、模型离线、资料删除和成员撤权。
- [ ] 运维联系人、故障升级方式、定时任务与备份失败告警已配置。
- [ ] 发布记录和观察期报告归档。
