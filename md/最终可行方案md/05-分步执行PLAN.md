# 分步执行 PLAN

初始状态：全部未实施。每步完成后更新：负责人、开始/结束日期、证据路径、遗留问题。每个勾选框表示该步全部验收通过，不表示文件已经创建。

## 1. 顺序、里程碑与工作量

```text
P01 → P02 → P03 → P04 → P05 → P06 → P07 → P08 [G0 可行性]
→ P09 → P10 → P11 → P12 → P13 → P14 → P15 → P16
→ P17 → P18 → P19 → P20 → P21 → P22 → P23 [G1 内部试点]
→ P24 → P25 → P26 → P27 [G2 生产上线]
→ P28 → P29 → P30 [G3 结构化记录]
```

可在依赖满足后交错安排前后端工作，不要求采用多代理或同时改同一文件。按顺序执行是默认可行路径。

| 分组 | 步骤 | 参考工程人日 | 产出 |
|---|---|---|---|
| 验证 | P01–P08 | 8–12 | 样本、模型基线、可解释的 RAG 验证链路 |
| 后端内核 | P09–P16 | 15–22 | 数据、权限、任务、发布、检索和问答 |
| 产品与质量 | P17–P23 | 13–20 | 可操作界面、效果优化、端到端验收 |
| 上线 | P24–P27 | 5–8 | 容量、恢复演练、运维和试点发布 |
| 记录增量 | P28–P30 | 5–9 | 记录导入、同步、引用和评测 |

V1.0 合计约 41–62 工程人日，V1.1 另计。此预算比此前建议稿更细，包含正式发布协议和撤权一致性，不是固定交付承诺；不含硬件等待、样本收集等待与用户观察期。1 人按每周 5 个有效工程日约 8–13 周，另留 20%–30% 风险缓冲；2 人不能简单除以二。P08、P23 后重新估算。

统一完成定义：实现/文档同步、必要测试通过、关键失败路径验证、可复现说明写入证据目录。测试报告应记录实际命令和结果，不能只写“通过”。

## 2. 阶段 A：可行性验证

### [ ] P01 盘点场景、资料与硬件

- 前置：本方案。
- 行动：选一个首批场景；统计资料格式/大小/页数与更新频率；挑 20–50 份代表资料；登记真实 CPU/GPU/显存/内存/磁盘/OS；明确模型准确名称、团队和数据出域边界；决定记录接入属于 V1.0 还是 V1.1。
- 交付：`docs/project-baseline.md`、资料清单、模型/硬件清单、待确认项责任人。
- 验收：清楚谁用、问什么、何时算答对；不把十万文档与十万 chunks 混用；有可使用的真实资料。
- 失败处理：资料未准备可用脱敏样本验证工程，但不得将其效果当作业务验收。

### [ ] P02 建立工程与可复现环境

- 前置：P01。
- 行动：建立前后端/infra/eval/docs 目录；固定 Python、Node、包管理器；生成锁文件；开发 PostgreSQL+pgvector、Redis、共享文件卷；配置 lint/typecheck/test 入口和 `.env.example`；密钥忽略规则。
- 交付：项目骨架、开发 Compose、锁文件、环境启动说明、CI 基础流程。
- 验收：新环境按 README 安装启动；数据库扩展可用；API 与 worker 容器可访问同一测试文件；仓库无真实密码。
- 失败处理：先修依赖兼容与网络/卷路径，不用手工改本机掩盖不可复现配置。

### [ ] P03 验证模型服务与设备容量

- 前置：P02、真实模型清单。
- 行动：逐一验证嵌入、生成、重排候选；记录版本/协议、维度、tokenizer、显存峰值、延迟；验证 query/doc 编码模板；再测模型共存与服务超时。
- 交付：`docs/model-compatibility.md`、模型 profile 文件和合法启动说明。
- 验收：一个可稳定访问的生成模型、一个 1024 维嵌入配置；错误输入被拒绝；服务并发预算明确；不依赖未上架硬件。
- 失败处理：小模型/分时运行/独立设备择一形成 ADR；重排不可用暂关闭，不阻塞单路验证。

### [ ] P04 建立问题与证据评测集

- 前置：P01 样本。
- 行动：整理 50–100 条问题，标注证据位置、答案要点、无答案标签；纳入编号、追问、跨段落、冲突、权限问题；划分调参与留出集。
- 交付：`eval/datasets/pilot.jsonl`、评分说明、数据使用范围。
- 验收：每条有明确评分依据；留出集不用于日常调参；数据中无未经允许的敏感资料。
- 失败处理：先完成 20 条人工可判定问题探路，后续必须补齐才进入 G1。

### [ ] P05 实现代表格式解析

- 前置：P02、P04。
- 行动：实现统一 DocTree/Block/Locator；接入 Markdown/TXT/DOCX；用真实 PDF 比较主解析路径；记录空文本、乱码、扫描页和表格告警。
- 交付：解析适配器、版本标识、golden 样本、结构预览文件。
- 验收：标题/正文顺序和原文定位可人工核对；坏文件、空文件返回明确状态；PDF 为主要资料时不得只验 Markdown。
- 失败处理：定位格式特征并更换/补一个解析器，记录首版不支持清单；不能无提示吞掉页面。

### [ ] P06 实现结构切片与编码输入

- 前置：P03、P05。
- 行动：按段落/章节切片，超长按句子/token；保留 locator/section_path；计算 embed_text/hash/token 数；验证标题前缀和 overlap。
- 交付：切片模块、ingestion/embedding profile 初版、边界样本。
- 验收：不超模型输入限制，中文/长条款/短段均可处理；同一输入与 profile 产物稳定；不能只有内容 hash 却丢来源。
- 失败处理：在调参集修结构规则，避免靠扩大 chunk 无限制掩盖解析错误。

### [ ] P07 跑通最小检索与引用问答

- 前置：P03、P06。
- 行动：临时 schema 中保存源版本、chunk、固定 profile；精确向量检索；上下文预算；调用生成；输出原文定位与简易 JSON trace。
- 交付：可重复执行的验证脚本、示例回答和 trace。
- 验收：一条问题能追到 query→候选→上下文→答案→原文；无证据不编造引用；不同模型空间不能混写。
- 失败处理：分解为解析、召回、上下文、生成问题逐项修正，不增加管理页面。

### [ ] P08 可行性评估与 G0 决策

- 前置：P04、P07。
- 行动：执行调参集和首轮留出验证，输出错误分类、模型资源基线；给出继续/调整结论及剩余风险；重估工期。
- 交付：`eval/runs/g0/report.md`、选定技术 ADR、范围与资源基线。
- 验收：证据链可行，主要资料格式可读，失败有可验证修复路径；建议启动门槛为有答案题 Evidence Recall@10 ≥80%、答案可用率 ≥70%，且无跨权限暴露；这不是上线门槛。
- 失败处理：返回 P03/P05/P06，修改后重测；若样本不适合文档 RAG，先调整产品范围。

## 3. 阶段 B：正式后端与可靠内核

### [ ] P09 建立正式数据迁移

- 前置：G0。
- 行动：按 02 的依赖顺序建表与复合外键；实现不可变 profile、source/artifact、build/release、任务和追踪；补循环指针约束；把 V0 测试数据通过正式导入重建。
- 交付：Alembic 迁移、ER 图、初始化命令、数据字典。
- 验收：空库升级成功；跨租户关联被拒绝；重复初始化幂等；JSON ID 不丢精度；active release 不能跨库引用。
- 失败处理：修改迁移并在全新测试库复验，禁止直接在生产库手工修结构。

### [ ] P10 身份、组织与知识库权限

- 前置：P09。
- 行动：session 登录/登出、Argon2id、CSRF、账号停用；组织/库成员角色；Repository 强制作用域；针对所有读写路径写负向权限测试。
- 交付：认证授权模块、权限矩阵测试、初始化管理员的一次性流程。
- 验收：两个租户互不可读；同组织非成员不能读库；会话仅 owner 访问；撤销 session 即失效；无默认公共密码。
- 失败处理：任何越权都阻塞后续对真实用户开放；修复后回归全部入口。

### [ ] P11 内容存储与版本接口

- 前置：P09、P10。
- 行动：Storage 接口、staging→confirmed、上传验证、文档/版本列表、受鉴权原文件下载；删除状态与 epoch；共享卷配置。
- 交付：文档 API、文件存储实现、失败对象清理命令。
- 验收：新版本不覆盖旧文件；坏类型/超限拒绝；文件键不受用户路径控制；API/worker 跨容器读取一致；访问旧文件也鉴权。
- 失败处理：对账孤儿文件与数据库引用，修复两阶段写入，再继续异步任务。

### [ ] P12 持久任务与 Outbox

- 前置：P09、P11。
- 行动：同事务写 task/outbox，派发器、租约/fencing、逐项状态、退避重试、取消、超时回收；解析/嵌入队列分开限流。
- 交付：任务内核、任务 API、Redis 重启与重复投递测试。
- 验收：投递失败能补发；重复消息不重复产物；旧 worker 不能覆盖新状态；进度来自已提交项。
- 失败处理：停止自动发布，修复幂等与恢复协议，禁止用“清空队列重来”作为唯一恢复手段。

### [ ] P13 接入正式入库流水线

- 前置：P05、P06、P12。
- 行动：解析/切片/嵌入接正式实体；保存 artifact manifest；接入 profile 兼容校验、失败项重试和 partial 告警。
- 交付：上传到 ready artifact 的完整后台链路、切片预览 API。
- 验收：模型超时、worker kill 后可继续；重试不会重复 chunks；无效维度无法写入；partial 不静默发布。
- 失败处理：按 task_item 定位失败阶段，复用完成产物，只重跑受影响项。

### [ ] P14 构建、发布与回退

- 前置：P13。
- 行动：快照清单、复用产物、input_epoch、ready 校验、发布 CAS、兼容 runtime、保留版本、清理引用检查。
- 交付：build/release API、发布差异、并发冲突与回退测试。
- 验收：半成品不能发布；改 prompt 不重嵌入；两个发布者不会相互覆盖；构建中修改内容会阻止陈旧发布；回退不会复活删除内容。
- 失败处理：保留旧 active release；将候选标为失败或过期，重建清单后再发布。

### [ ] P15 正式检索与证据组装

- 前置：P14、P10。
- 行动：基于 release/profile 精确检索；统一授权与有效内容过滤；query 改写开关、chunk 去重、预算、引用 evidence 编号和 trace。
- 交付：检索服务、search-test API、无答案与空索引响应。
- 验收：结果只来自当前固定 release 中有效来源；停用即时生效；预算包含系统/历史/输出预留；trace 能解释候选消失原因。
- 失败处理：关闭未经验证的改写/扩展，用精确单路基线定位问题。

### [ ] P16 流式对话、引用与历史可见性

- 前置：P15。
- 行动：run 状态机、幂等键、SSE 事件、取消、断线恢复查询；引用映射；保存 message_evidence；历史回答动态授权和失效隐藏。
- 交付：会话 API、生成适配器、引用/反馈 API、网络中断测试。
- 验收：一个 run 一个终态；重连不重复生成；错误引用不当成功；删除/撤权后停止后续输出，历史答案不泄漏不可见来源。
- 失败处理：保留 interrupted/invalidated 状态，不将 partial 伪装 completed；修复一致性后再接前端用户。

## 4. 阶段 C：可用产品与检索质量

### [ ] P17 前端外壳与文档管理

- 前置：P10–P13 API 可用。
- 行动：shadcn-vue 布局/路由/登录；知识库、上传、过滤分页、任务与文档详情；组件边界按 04 执行。
- 交付：可操作管理端及 loading/empty/error/forbidden 状态。
- 验收：普通用户能上传并定位失败原因；过滤重置分页；离页停止轮询；权限按钮与服务端一致。
- 失败处理：修正接口/状态契约，不通过前端写死“成功”绕过后端。

### [ ] P18 问答与引用界面

- 前置：P16、P17。
- 行动：会话历史、流解析、停止/重试、引用侧栏、反馈、安全 Markdown、无证据与索引未就绪状态。
- 交付：完整提问→回答→原文核对用户流程。
- 验收：网络分片不破坏事件；断线能查最终状态；键盘操作可用；内容撤权后清理敏感页面状态。
- 失败处理：对照事件日志重现，不用无限重连自动提交相同问题。

### [ ] P19 配置、发布与检索调试界面

- 前置：P14、P15、P17。
- 行动：预设配置、高级表单、变更影响、构建进度、候选差异、发布/回退；检索候选与阶段耗时。
- 交付：管理员闭环与角色分离。
- 验收：用户明确配置是否需重建；过期构建不可发布；读者看不到原始调试内容；回退范围与保留期清楚。
- 失败处理：先保留少数稳定预设，避免开放未实现的任意参数。

### [ ] P20 词法召回、融合与重排实验

- 前置：P04、P15、P19。
- 行动：固定中文分词/词典，生成 tsvector/GIN；编号精确匹配；实现 RRF 和可开关重排；在同一条件下比较各方案。
- 交付：可配置检索策略、对比报告、选定默认 runtime。
- 验收：调参集提升在留出集未明显回退；重排成本有记录；各路过滤一致；不将 ts_rank 称为 BM25。
- 失败处理：保留最优简单基线；只有明确失败证据才引入专用检索引擎。

### [ ] P21 HNSW 与过滤后召回验证

- 前置：P20、代表规模数据。
- 行动：建匹配的 cosine HNSW；对比精确检索；测试 tenant/kb/release 窄范围过滤、准备语句、iterative scan 与扫描上限；记录 EXPLAIN。
- 交付：索引迁移、参数基线、ANN recall/延迟报告。
- 验收：目标负载下效果与延迟达标；不足 k 情况可解释；高选择性过滤不悄悄失去大量证据。
- 失败处理：调整扫描/物理分区或对小范围用精确检索，不通过减少权限过滤改善性能。

### [ ] P22 一致性与权限破坏测试

- 前置：P16、P19、P21。
- 行动：执行 06 中删除、撤权、回退、模型换代、worker 崩溃、outbox 重放、并发发布、路径与 Markdown 恶意输入用例。
- 交付：回归报告、修复记录、重新执行结果。
- 验收：数据正确性和授权关键用例全部通过；新 profile 不污染旧索引；无失效内容经历史回答绕过。
- 失败处理：任何关键失败都阻止 G1，回到责任步骤修复。

### [ ] P23 内部试点与 G1 验收

- 前置：P17–P22。
- 行动：让 3–5 名目标用户完成真实任务；独立留出集人工评分；整理资料缺口/产品问题；重估剩余容量与上线工作。
- 交付：G1 报告、问题优先级清单、被接受的限制说明。
- 验收：达到 06 的质量门槛与关键流程标准，用户能自行上传、发布、问答、核对引用。
- 失败处理：按错误归因返工；不以好看的页面或个别成功示例替代验收。

## 5. 阶段 D：生产准备

### [ ] P24 生产部署与隔离

- 前置：G1、实际目标设备可用。
- 行动：锁镜像、TLS、内部网络、生产凭据与独立卷、健康检查、数据库迁移、限流；文件/DB 放合适磁盘；监控模型与任务。
- 交付：生产 Compose/部署脚本、端口清单、配置模板、runbook。
- 验收：干净主机可重复部署；开发无法误写生产；只有授权入口可达；无 secrets 入仓库。
- 失败处理：停留在试点，不假设改 endpoint 就完成生产化。

### [ ] P25 容量与并发基线

- 前置：P24。
- 行动：在 1/5/10 并发下测试冷/热检索和生成；同测重建+在线问答；记录首字、完整耗时、token 数、错误率、显存/磁盘峰值。
- 交付：容量报告、限流/队列/并发配置、实测 SLA。
- 验收：商定负载下无 OOM，P95 达标，超载有可解释的 429/排队；不承诺未测试容量。
- 失败处理：降低上线并发/输出预算，拆模型资源或调整部署；修改 SLA 必须在上线说明中体现。

### [ ] P26 备份恢复与回滚演练

- 前置：P24、P25。
- 行动：做含数据库+原文件+profile 的一致性备份；在隔离环境恢复；验证原文/引用/检索；演练应用版本和 release 回退。
- 交付：恢复脚本、备份清单、RPO/RTO 实测、演练日志。
- 验收：恢复后能打开真实文件、定位引用、检索相同版本；没有仅恢复 DB 而丢文件；失效/删除政策仍成立。
- 失败处理：修复备份流程并重新完整演练，禁止带失败恢复记录上线。

### [ ] P27 G2 上线与观察

- 前置：P22 回归仍通过、P23/P25/P26 验收。
- 行动：冻结发布版本；确认容量与限制；小范围导入真实资料；管理员验收；逐步开放用户；观察至少 5 个工作日并归档问题。
- 交付：发布记录、使用手册、值守与问题升级联系人、观察报告。
- 验收：质量/错误率/队列稳定，无未解决阻断问题；日常重试、更新、备份可由维护者执行。
- 失败处理：停止扩大范围，必要时切回保留 release/应用版本；数据结构回退按 expand-contract 策略处理。

## 6. 阶段 E：结构化记录

### [ ] P28 定义记录源契约与迁移

- 前置：G1；默认在 G2 后，若 P01 提升范围则加入上线前置。
- 行动：定义 external_id、payload、字段映射、更新/删除语义；扩展 record_sources/records/record_versions 与 artifact/release 来源约束。
- 交付：记录 schema、输入示例、兼容迁移、数据源责任人。
- 验收：文件与记录来源恰好一个；迁移不破坏 V1.0 文档；明确不支持自由统计查询。
- 失败处理：收窄到一个已知记录结构，暂不实现通用连接器。

### [ ] P29 记录导入、增量与删除

- 前置：P28、任务与发布内核。
- 行动：JSONL/CSV 上传、字段预览、差异、版本令牌；upsert/delete、hash 跳过、水位、失败恢复；统一 build/release。
- 交付：导入 API/UI、记录定位与失败报告。
- 验收：增量文件缺失项不误删；重复导入幂等；全量删除差异可预览；记录删除即时失效。
- 失败处理：阻止发布异常批次，按记录恢复，不默默跳过错误行。

### [ ] P30 记录问答与 G3 验收

- 前置：P29、P20。
- 行动：文档+记录混合样本评测；来源/字段引用、更新时效、权限回归；识别需精确结构化计算的问题并说明限制。
- 交付：V1.1 报告、用户说明、同步与恢复 runbook。
- 验收：语义问题可定位记录，数值统计不伪装成准确全库计算；总体质量不回退，更新/删除测试通过。
- 失败处理：独立关闭记录召回，文档问答继续可用；修正映射与检索后重新验证。
