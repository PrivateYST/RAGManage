# 代码注释规范

## 适用范围

本规范是 RAGManage 的项目级强制规则，适用于仓库内所有前端、后端、脚本、配置、数据库迁移和测试代码。所有新增或修改的代码都必须包含与其职责和复杂度相匹配的有效注释。

## 基本要求

1. 所有代码文件都必须通过文件头注释、模块注释或同等形式说明该文件的用途、职责和边界。
2. 所有类、组件、函数、方法、Hook、Composable、Store、接口、类型及重要常量都必须说明其用途；存在参数、返回值、异常、副作用或调用限制时必须一并注明。
3. 所有接口处理、业务规则、权限判断、状态转换、数据转换、异常处理、并发处理、缓存策略和非直观算法都必须说明“为什么这样做”，以及必要的前置条件和边界情况。
4. 前端代码必须对组件职责、关键交互、状态来源、异步流程、复杂响应式逻辑及重要 UI 分支添加注释。
5. 后端代码必须对模块职责、服务边界、接口契约、领域规则、事务、鉴权、数据访问及异常语义添加注释。
6. 测试代码必须说明测试场景、关键前置条件和预期行为；回归测试应注明其防止复现的问题。
7. 配置项、环境变量、正则表达式、魔法数字、兼容性处理和临时解决方案必须说明含义、原因及适用范围。
8. 修改代码时必须同步检查并更新相关注释；失效、错误或与实现不一致的注释视为缺陷，不得保留。

## 注释质量

- 注释应解释意图、约束、取舍和原因，不能只把代码语句翻译成自然语言。
- 注释应简洁、准确、可维护，并与当前实现保持一致。
- 优先使用项目所用语言或框架的标准文档注释格式，例如 Python Docstring、JSDoc/TSDoc、Vue 组件注释等。
- 对一眼即可理解的语句，无需机械地逐行复述；但代码所属文件、公开能力、业务规则和非显而易见的实现必须有注释覆盖。
- 禁止使用无信息量的占位注释，例如“处理数据”“执行逻辑”“定义变量”。

## 提交与审查

- 未提供必要注释的新增或修改代码不得视为完成。
- 代码审查必须将注释完整性、准确性和时效性作为必检项。
- 若代码难以用简洁注释解释，应优先简化或重构实现，再补充必要注释。
