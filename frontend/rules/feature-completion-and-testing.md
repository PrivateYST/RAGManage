# 功能完成与测试规则

## 适用范围

本规则适用于项目中的所有业务功能、接口、页面、任务流程和数据变更。功能只有在形成完整业务闭环并完成适当测试后，才能标记为完成。

## 完整业务闭环

1. 不得只完成页面、接口、数据库或后台任务中的单独一层。
2. 功能应按实际业务覆盖完整链路：入口与权限检查 → 用户操作 → 服务端处理 → 数据持久化或任务执行 → 前端状态反馈 → 结果查询、失败处理或恢复。
3. 页面中的按钮、表单、筛选、分页、弹窗和状态展示必须连接真实业务能力，不能以静态占位、模拟数据或不可操作控件作为完成结果。
4. 异步功能必须具备明确的进行中、成功、失败、重试、取消或恢复状态；用户能够查询最终结果。
5. 涉及权限、租户或空间的数据必须验证授权范围和隔离边界，禁止跨空间泄露。

## 测试要求

1. 每项功能都必须设计并执行可复现的测试流程。
2. 测试至少覆盖与本次改动相关的：
   - 主要成功路径；
   - 参数校验和失败路径；
   - 权限与数据隔离；
   - 边界条件和重复操作；
   - 状态持久化、恢复或回滚。
3. 根据改动范围执行适合的静态检查、类型检查、单元测试、接口测试、组件测试或端到端测试。
4. 关键业务流程必须在真实运行环境中完成一次实际操作验证，确认前端、后端、数据库和依赖服务能够协同工作。
5. 修复缺陷时应验证原问题已消失，并检查相关主流程没有回归。
6. 可逆、低影响的纯样式调整不强制编写无意义的自动化测试，但仍须执行已有静态检查，并进行页面实际验收。

## 完成判定

出现以下任一情况时，不得将功能标记为完成：

- 自动化测试或必要检查失败；
- 只有页面、接口或数据层的局部实现；
- 使用占位数据，或关键操作按钮无法实际执行；
- 成功、失败或异步状态无法追踪；
- 权限、租户隔离、异常处理或恢复流程尚未验证；
- 实际运行结果与需求不一致。

计划文件中的任务复选框只有在功能闭环实现、测试通过并完成必要的真实环境验证后，才能从 `[ ]` 更新为 `[x]`。

## 完成报告

每项任务完成时应说明：

- 已实现的业务闭环；
- 执行的测试或检查命令；
- 测试数量和结果；
- 真实环境验证过程与结果；
- 仍然存在的限制或后续事项。
