# 组件优先与交互反馈规范

## 适用范围

本规范适用于 `frontend` 下所有页面、组件、交互和样式代码。它与项目设计规范、业务组件目录规范一起执行；发生冲突时，以更严格的要求为准。

## 强制规则

1. **组件优先**：实现页面或交互前，必须先检查项目现有组件以及 shadcn-vue、Reka UI 中是否已有合适能力。优先组合和复用组件，禁止在已有组件能够满足需求时重新实现同类组件。
2. **优先使用 shadcn-vue**：按钮、输入框、选择器、下拉菜单、卡片、表格、分页、弹窗、抽屉、表单和导航等通用 UI，默认使用 shadcn-vue 风格及其组件实现。
3. **样式使用 Tailwind CSS**：组件和页面样式优先使用 Tailwind CSS utility classes 及项目现有语义变量。只有在 Tailwind 无法合理表达、第三方组件适配或确有复杂样式需求时，才允许补充 CSS；补充 CSS 必须局部、必要且不能重复建立一套组件样式系统。
4. **提示统一使用 AppToast**：保存成功、删除成功、提交失败、请求异常、复制成功等操作结果提示，统一使用 Reka UI 的 AppToast 能力或项目基于 Reka UI 封装的 AppToast 组件。禁止使用 `alert()`、临时文本或自行实现的提示浮层替代。
5. **删除操作使用 AlertDialog**：删除、批量删除、移除、停用等具有破坏性的操作，优先使用 shadcn-vue / Reka UI 的 `AlertDialog` 组件确认。确认弹窗必须说明对象和后果，并提供明确的取消与确认操作；确认完成后再执行请求，并通过 Toast 反馈结果。
6. **保持组件语义**：交互必须使用语义化组件和明确的状态、变体、禁用态、加载态及键盘焦点。不得为了视觉效果绕过组件的可访问性和交互约定。
7. **样式必须隔离**：每个页面和组件的自定义样式必须使用隔离作用域，避免样式跨页面、跨组件互相覆盖。Vue 单文件组件优先使用 `<style scoped>`；Tailwind class 应限制在当前组件模板中使用，不得通过宽泛标签选择器或全局类名污染其他页面。
8. **确需自定义时先说明原因**：当现有组件无法满足需求而必须新建组件或样式时，应在代码注释或相关文档中说明复用检查结果、无法复用的原因和组件边界。

## 实现顺序

实现前按以下顺序选择方案：

1. 项目已有业务组件或通用组件；
2. shadcn-vue / Reka UI 基础组件组合；
3. 使用 Tailwind CSS 完成布局和样式调整；
4. 最后才考虑新增组件或局部 CSS，并记录必要性。

## 禁止事项

- 不使用原生 `alert()`、`confirm()` 或自制删除确认弹窗。
- 不为已有 shadcn-vue / Reka UI 能力重复封装视觉和交互相同的组件。
- 不使用大段页面级 CSS 替代 Tailwind CSS，也不创建脱离现有语义变量的私有色板。
- 不在页面组件中使用无作用域的 `<style>`、宽泛的全局选择器或容易冲突的通用类名。
- 全局样式仅用于 reset、主题变量、字体和确需全局生效的基础规则，并必须集中维护、明确用途。
- 不用成功、错误提示颜色或动效装饰页面；反馈只表达真实操作状态。
