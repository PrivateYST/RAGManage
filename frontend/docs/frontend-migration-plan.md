# 前端功能目录迁移计划

## 目标与完成标准

将 `frontend/src/views` 中的页面和页面子功能逐项整理为可独立维护的功能目录，遵守 `frontend/AGENTS.md` 引用的规则及 `frontend/rules/` 下的页面结构、子视图、组件复用、表格、设计和测试要求。迁移只调整代码边界，不改变现有路由、权限、接口契约和用户可见行为。

单项只有同时满足下列条件才可勾选：

- 页面目录具备职责清晰的 `index.vue`、`index.ts`、`type.ts`；有枚举时有 `enum.ts`，有页面样式时有隔离的 `index.scss`。
- `index.vue` 只负责模板和组件编排；状态、请求和业务操作位于逻辑模块。
- 页面内的业务子页、表单弹窗、详情弹窗和抽屉各自在 `components/<FeatureName>/` 中维护，并遵守相同的文件职责规则。
- 通用业务组件放在 `src/components/<ComponentName>/`，并从 `src/components/index.ts` 导出；页面表格使用 `AppTable`。
- 注释准确且说明职责、业务约束和异步边界；不保留失效注释。
- 执行相关测试、类型检查、lint、格式检查和构建；关键业务流程完成可复现的运行验证。只有通过的检查才记录为完成。
